[ Slide 01 / 05 ]    Introduction · Ideation · Brief Description [ Brahmadatta AI ]

Autonomous armor
for software.

An authorised, defensive Cyber-Reasoning System for AI Kavach. Given a C/C++ repository you own, Brahmadatta finds a real memory-safety defect with its own fuzzing, drafts a patch with a self-hosted model, and lets deterministic tools — not the model — deliver the verdict.
[ Problem ]

Scanners and “AI security” tools stop at the report. They hand a human a finding and a suggested patch — and a suggested patch, accepted on model confidence, is exactly how a plausible-looking wrong fix ships to production.

[ Idea & Motivation ]

Close the loop, and make the machine check its own work. Discover → minimise to a deterministic reproducer → patch with a local model → let the reproducer, the regression suite, static checks and renewed fuzzing decide.

[ The Differentiator ]

The same pipeline visibly rejects a patch that eliminates the crash but breaks the program's behaviour. Every competitor shows a patch that worked; we show our system refusing one that only looked like it did.

[ Defensive / Authorised-Use Boundary ]

Authorised repositories and isolated environments only; write-once authorization record + server-verified snapshot hash. No public-target scanning, no exploit deployment, no automatic production merge. Repository content never leaves for a hosted inference API — structurally enforced.

[ The mission, one line ] authorize → ingest → baseline → analyze → correlate → stress‑test → patch → verify → export evidence

[ Slide 02 / 05 ]    Detailed Methodology [ The Mission — Nine Steps ]

One pipeline. Unattended after a single [ START ].

[ Tier 1 · Deterministic Triage ]
  • 01 Authorize + snapshot. Immutable snapshot; sha256 recomputed server-side and matched.
  • 02 Baseline. configure → build → CTest on the pristine tree. Pass/fail counts recorded — the denominator every later verdict is checked against.
  • 03 Analyze. Semgrep (offline C/C++ ruleset) + compiler warnings parsed into structured findings; git-history summary.
[ Tier 2 · Sandbox + Lightweight Patch ]
  • 04 Stress-test. ASan/UBSan build + libFuzzer campaign in a locked-down container. Sanitizer-confirmed heap-buffer-overflow with a stack trace; crashes deduplicated.
  • 05 Correlate + minimise. Bind the crash to a source location; minimise the input to a reproducer that replays 5/5 from a clean build; persist it durably.
  • 06 Patch. A self-hosted CodeLlama 7B model gets the crash report + localised source. Patch policy (single file, allowlist, changed-line cap) must pass before compile.
[ Verification & Proof-of-Fix ]
  • 07 Verify — every policy-passing candidate, identical gate sequence. The verifier is provenance-blind: it cannot see the model, its confidence, or its rationale.
  • 08 Proof-of-fix. The verdict is derived from the gate matrix, never from confidence.
  • 09 Export + teardown. report.md / .json, gate matrix, content-addressed artifacts, sha256 manifest. Sandbox + model-host release confirmed, zero strays.

[ What the loop catches ]

Patch A — the correct fix — is marked VERIFIED. Patch B kills the crash by deleting the feature that was overflowing: it passes compile, eliminates the reproducer, then fails a regression test (six assertions in the tab-expansion case) → REJECTED, beside the accepted one. An overfit patch that fools every static gate is caught by renewed fuzzing of the patched build.

[ Slide 04 / 05 ]    Salient Features & Novelty [ Resource Utilisation · Novelty · Lightweight ]

The system rejects its own patch —
the rejection is a real regression-test failure, not a scripted demo beat.

[ Novelty — verification that overrules the model ]
  • Evidence-gated escalation. Nothing reaches the model until deterministic tiers produce a confirmed, minimised finding.
  • No confidence path. derive_verdict() takes one argument — the gate matrix. A VERIFIED record over a failing gate cannot be constructed.
  • Provenance-blind verifier. The operator-supplied “bad” candidate takes a genuinely identical path.
  • Overfit caught by renewed fuzzing of the patched build — not by a human already knowing which input to try.
  • Disclosure as a feature. A gate that did not run is as loud as a failure; the verdict carries its denominator.
[ Posture — self-hosted · authorised · isolated ]
  • Repository content never reaches a hosted API. Enforced three ways: internal-only compose network, a single-inference-client source test, a boot-time system check that refuses a hosted endpoint.
  • Rootless isolated execution — --network none, all capabilities dropped, non-root, read-only rootfs. Egress denial proven by a live DNS+TCP test.
  • Authorised repositories only — write-once record, server-verified snapshot hash. No public scanning, no exploit deployment, no auto-merge.
  • Operator-visible Command Center — every panel reads the same stream that produces the evidence bundle.
[ Resource utilisation & lightweight design ]
  • CPU-first. Rented GPU cut entirely. A local 7B model with a process-level lease and confirmed teardown.
  • 4 application processes vs 15 in the original design. Postgres SKIP LOCKED instead of a message broker. No Redis, no S3, offline Semgrep ruleset.
  • Runs on one machine, offline. Orchestrator / worker / gateway / evidence are modules in one Django project.
